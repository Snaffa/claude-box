claude-box: run Claude Code in a container, for any project under ~/Projects
============================================================================

One long-lived container ("claude-box") holds every project. Herdr runs
inside it: one Herdr workspace per project, each with its own Claude, and a
sidebar showing which ones are working, blocked or idle. You open it from the
host with claude-box.sh.

What the container can see
--------------------------
  ~/Projects             read-write (all projects, same paths as on the host)
  ~/Projects/claude-box  read-only  (so Claude can't widen its own mounts)
  ~/Projects/.devcontainer read-only
  ~/.claude/projects     read-write (Claude memory + session history, shared with host)
  ~/.gitconfig           read-only  (commit identity; no ssh key or credentials,
                                     so no pushing)
  ~/Documents/References read-only  (reference papers)
  ~/server               read-only  (sshfs share of ebncsm2:/mnt, mounted at login
                                     by niri autostart; needs user_allow_other in
                                     /etc/fuse.conf). Must be mounted before the
                                     container starts, otherwise it shows up empty.
Nothing else: no ssh client or key, nothing writable on the lab. Because of
that, `claude` inside the container is an alias for
`claude --dangerously-skip-permissions`.

Docker volumes (survive rebuilds and container recreation):
  claude-box_claude-config  Claude's login and settings (not your real ~/.claude)
  claude-box_herdr-state    Herdr's config and saved workspaces

The container is long-lived: packages an agent installs (pip, conda) stay
until the container is recreated (see "Reset the container" below).


1. One-time setup: install Docker
---------------------------------
  sudo pacman -S docker docker-compose docker-buildx
  sudo systemctl enable --now docker
  sudo usermod -aG docker $USER

Then log out and back in.
Note: being in the docker group is equivalent to root on this machine.


2. Build the image
------------------
Run from anywhere:
  ~/Projects/claude-box/claude-box.sh build

The first build is slow (conda environments with pytorch, gmsh, vtk).
Rebuild whenever:
  - a project's environment.yml changes
  - you add a new project that has an environment.yml
  - you want a newer Claude Code or Herdr version
A rebuild only takes effect once the container is recreated (see "Reset").


3. First start (one time)
-------------------------
  ~/Projects/claude-box/claude-box.sh
This starts the container and opens Herdr. Detach (Ctrl+B then q), then
install Herdr's Claude integration inside the container (saved in the
claude-config volume, so only once):
  docker exec claude-box herdr integration install claude
In the first Claude you start, type /login. The login is saved in the volume.


4. Daily use
------------
Open:      ~/Projects/claude-box/claude-box.sh
           (starts the container if needed, then attaches to its Herdr;
           also started at login by niri autostart in an Alacritty window)
Detach:    Ctrl+B then q, or just close the window.
           Herdr and every Claude keep running inside the container.
Reopen:    run claude-box.sh again.

New project workspace (from any pane inside Herdr):
  herdr workspace create --cwd ~/Projects/<project> --label <project>
then run `claude` (or `claude --resume`) in it.

The conda environment follows the folder: cd into ~/Projects/<project> and
env "<project>" activates (projects without an environment.yml use base).

Herdr keys (prefix Ctrl+B): v split right, - split down, c new tab, q detach.
Check agents:  herdr agent list


5. Stopping
-----------
Restart Herdr only (container keeps running; ends all panes and Claudes):
  docker exec claude-box herdr server stop
Stop everything (container and all sessions):
  ~/Projects/claude-box/claude-box.sh stop
After a reboot the container is stopped; claude-box.sh starts it again.
Conversations are kept on the host (~/.claude/projects): `claude --resume`.


6. Reset the container
----------------------
To pick up a rebuilt image or throw away what agents installed:
  ~/Projects/claude-box/claude-box.sh stop
  docker rm claude-box
  ~/Projects/claude-box/claude-box.sh
Logins, settings and Herdr workspaces survive (they are in the volumes).


7. Work in VS Code (dev container)
----------------------------------
VS Code attaches to the same claude-box container. It only looks for
.devcontainer/devcontainer.json at the root of the folder you open, so that
file lives at ~/Projects/.devcontainer -- versioned here (devcontainer.json,
compose.devcontainer.yaml, root.dockerignore) and symlinked into place. One
time per machine, after cloning this repo into ~/Projects/claude-box:
  cd ~/Projects
  mkdir -p .devcontainer
  ln -s ../claude-box/devcontainer.json .devcontainer/devcontainer.json
  ln -s ../claude-box/compose.devcontainer.yaml .devcontainer/compose.devcontainer.yaml
  ln -s claude-box/root.dockerignore .dockerignore
(root.dockerignore matters: without it, VS Code's build uploads everything
under ~/Projects -- including datasets -- as the Docker build context.)

Then:
  code ~/Projects        then: Ctrl+Shift+P > "Dev Containers: Reopen in Container"
Files, terminals, Python/Jupyter and the Claude Code extension then run in
the container. Note: "Dev Containers: Rebuild Container" recreates the
container, which ends the Herdr sessions in it.


Troubleshooting
---------------
- Build fails while creating an environment:
    one project's environment.yml doesn't solve; the log line
    "=== creating env for <project> ===" shows which one.
- "container name claude-box is already in use" on start:
    an old container (e.g. from VS Code) holds the name: docker rm claude-box
- Claude not shown in Herdr's sidebar:
    the integration isn't installed; see step 3.
- ~/server is empty inside the container:
    the sshfs share wasn't mounted when the container started. Mount it on
    the host, then reset the container (step 6).
- Start over with a fresh login/settings:
    docker volume rm claude-box_claude-config


ssh to the lab (removed)
------------------------
Containers used to ssh to the ebncsm* servers with a dedicated key
(~/.config/claude-box/ssh) gated by ~/bin/claude-ssh-gate on the servers.
That was removed: the key is no longer mounted and the image has no ssh client.
